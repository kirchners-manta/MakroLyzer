# Domain documentation

Use a single-context layout:

- `GLOSSARY.md` at the repo root for domain terminology.
- `docs/adr/` for architecture decision records.

Before exploring, read the glossary and ADRs relevant to the task
when they exist. Proceed silently when they are absent; create
them only when terminology or decisions need recording.

Use the glossary's vocabulary in code, tests, and tickets.
Explicitly identify proposals that contradict an existing ADR.
